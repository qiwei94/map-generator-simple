# 美学闭环工作日志 — 2026-07-25

> 主题：从"狗啃边缘"批评 → 抗锯齿修复 → edge 指标 → **BO 生成模式纳入闭环可调** → 芝加哥全模式扫描完成（block_fill 胜出）

---

## 一、起点：问题诊断

用户批评 `output/aesthetic/chicago` 渲染图建筑街区边缘"坑坑洼洼、犹如狗啃"，不符合城市肌理与参考样例。像素级放大对比后确认问题成立，定位三层原因：

| # | 原因 | 结论 |
|---|------|------|
| 1 | 渲染无抗锯齿（12m/px 二值填充） | **主凶之一**，已修复 |
| 2 | 简化容差（`BUILDING_SIMPLIFY_TOL_M=25m` / `AGGREGATE_SIMPLIFY_M=60m`） | 闭环实证：25m/60m 竟是局部最优，双向探测都变差，**不是元凶** |
| 3 | `oriented_bbox` 与街区块相交切割产生毛刺 | **主凶之二**，由 block_fill 模式解决 |

## 二、今日代码改动

### 1. 渲染抗锯齿（review_render.py，重写）
- `SUPERSAMPLE = 2`：masks 与俯视合成均在 2x 栅格进行，最终 LANCZOS 降采样
- masks 从二值变为 [0,1] 浮点覆盖率（亚像素精度），同时供 metrics 使用
- A/B 对比（`_zoom_residential_AA.png` vs `_zoom_residential.png`）改善显著

### 2. 指标层（metrics.py）
- 新增 `_edge_metric`：BL+BO 外环拐角内角落在 [75°,105°] 的占比（网格城市近直角检验；方形=1.0，星形=0.533）
- coverage 从"目标带得分"改为单调 ramp（`clip(raw/hi, 0, 1)`）——修复目标带不可达导致的梯度死亡。**已知 Goodhart 风险：无上限惩罚**
- config.py 三个原型权重均加入 edge 指标

### 3. BO 模式纳入闭环（本日主线）
- **`_layer_preprocess.py`**：`_compute_BO` 加 `mode_override`，`preprocess_layers` 加 `bo_mode_override`，`eff_mode` 传入 `_aggregate_in_blocks`
- **`aesthetic/config.py`**：
  - `BO_MODES` = oriented_bbox / block_fill / density_fill / convex_hull / concave_hull / union / buffered_union（7 种，`_aggregate_in_blocks` 已有实现）
  - `PARAM_SPACE` 改 6 元组 `(lo, hi, init_step, min_step, is_int, live_modes|None)`；加回 `building_density_threshold`（live: block_fill/density_fill）、`building_count_threshold`（live: block_fill）
- **`param_controller.py` 完全重写**：两阶段控制器
  - 阶段 1 `mode_scan`：离散模式逐一试探，赢者换基点并 `_reset_steps()`
  - 阶段 2 `pattern_search`：模式感知连续爬山，`_live_params()` 按 live_modes 过滤死杠杆
- **`rerun_harness.py`**：seed_params 加 `bo_mode`，overrides 加 `bo_mode_override`（自动进 preprocess 缓存键）
- **`loop.py`**：加 `seed_override`/`modes` 参数；run() 末尾写 `best_config.json`（每城配置档案）
- **`run_aesthetic.py`**：加 `--fresh`/`--rescan-modes`；默认从 `best_config.json` 续跑并锁定模式

### 4. Bug 修复

- plateau 早停错杀 — `plateau_limit = max(PLATEAU_ROUNDS, 2 * len(controller.space))`
- 回归测试：**169 passed, 8 skipped**（pytest tests/ + auto_params/tests/）

## 三、芝加哥全模式扫描结果（已完成，16 轮）

命令：`python -m aesthetic.run_aesthetic --city chicago --fresh --rescan-modes --max-rounds 16`

**阶段 1 模式扫描**（基线 oriented_bbox = 6.508）：

| 模式 | 分数 | 判定 | 备注 |
|------|------|------|------|
| oriented_bbox | 6.508 | 基线 | coverage_raw 0.095, edge 0.752 |
| **block_fill** | **6.778** | ✅ 接受 | coverage_raw 0.219（翻倍），n_BO 6234→15521，regularity 0.315→0.352，edge 0.752→0.564 |
| density_fill | 6.626 | ✕ | 略逊于 block_fill |

## 四、关键结论

1. **block_fill 是芝加哥的最优 BO 模式**——整块填充贴合参考作品风格，覆盖率翻倍、规则度提升，验证了"模式入闭环"的核心假设。
2. **简化容差不是狗啃元凶**——真凶是渲染 AA 缺失 + oriented_bbox 切割，两者均已解决。
3. **凸包类模式对网格城市全面溃败**（landmark 出带归零），指标体系能正确否决明显的坏形态。
4. **待人眼确认**：edge 0.752→0.564 的形态变化（block_fill 更"饱满"但拐角减少），需目检 `r16_topdown.png` vs 参考样例确认不是"饱满但呆板"。

## 六、3D 桥接里程碑（generate_cli 接入 best_config）

2D 闭环学到的是**真实几何**（preprocess_layers 输出），3MF 建筑墙面直接继承。本日打通了 `best_config.json → generate_cli.py` 的断点：

- **generate_cli.py**：自动读取 `output/aesthetic/<city>/best_config.json`，注入 `bo_mode`/`simplify`/`density`/`count`/`print_limit`/`road_tier`（`_cfg` 猴补丁 + preprocess override）；新增 `--aesthetic-config` / `--no-aesthetic` 开关
- **关键修正**：芝加哥 18 万建筑会触发密度自动判定走 MERGE 两层模式（跳过 `_compute_BO`，block_fill 失效）→ 美学 `bo_mode` 存在时覆盖判定强制三层模式；显式 `--merge-layers` 仍优先
- **缓存安全**：注入参数（含猴补丁值）进 preprocess 缓存键，新旧几何不互相污染
- **tools/inspect_3mf_bridge.py**：validator 全规则校验 + 裁剪区域 3D 截图

### 芝加哥 3MF 实测结果（block_fill）

- 命令：`generate_cli.py --bbox 41.77,-87.77,41.99,-87.47 --pbf pbf_cache/illinois-latest.osm.pbf --city chicago`（bbox 与 aesthetic 对齐）
- 注入确认：`_compute_BO` 输出 **BO=15668**（与闭环 block_fill 轮 15502 一致，oriented_bbox 基线仅 ~6234）→ block_fill 几何确实进了 3D
- 产物：`output/chicago/full_chicago_0725_2214.3mf`（77MB，Buildings 311 万面 / Terrain 153 万面 watertight / BlockBase 162 万面），总耗时 800s
- **validator：10/12 通过**。两个 FAIL 与桥接无关：
  - V8 水体 Z 跨度 0.40mm 恰好卡阈值边界（`>=0.4` 的浮点边界）
  - V12 植被面非全平面（既有植被层问题）
