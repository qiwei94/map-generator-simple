# 打印感知的城市浮雕重构方案

状态：P0 已完成；P1 道路职责分离已实现，正在进行多城市默认值验收
工作分支：`agent/print-aware-foundation`

## 1. 目标与边界

当前管线已经零散考虑了喷嘴、道路宽度、水体宽度、建筑高度和材料颜色，
但这些约束分散在 `config.py`、自动参数、画廊 preset 和预处理函数中；部分参数
虽然被解析，却没有抵达实际几何路径。结果是同一套参数在 5、15、25 km 取景
中代表完全不同的可打印尺度，也容易出现“路网负责切块，同时又全部被画出来”
造成的黑、密、乱。

本次重构要建立一条可审计的确定性链路：

```text
PrinterProfile + 真实 bbox + 成品尺寸
        ↓
PrintScale / PrintConstraints
        ↓
城市特征分类与视觉焦点策略
        ↓
拓扑网络 → 结构缝网络 → 可见道路/水体
        ↓
语义 Z 量化 → 网格 → 3MF
        ↓
PrintReport + DesignSpec + 验证器
```

边界：

- LLM/VLM 只能建议场景类型、视觉焦点和审美权重，不能直接控制顶点、全局 Z、
  布尔运算或跳过验证器。
- `DesignSpec` 是导出后的审计记录，不反向驱动几何。
- 先用现有 OSM/DEM 做确定性改进；高德、Google 等多源融合暂不进入关键路径。
- 默认打印配置必须保持当前输出兼容；每个阶段用城市样品和 3MF 验证后再改变默认值。

## 2. 统一物理模型

### 2.1 PrinterProfile

第一阶段引入唯一的打印机配置对象，至少包含：

- 喷嘴直径；
- 挤出线宽；
- 层高；
- 最小可靠彩色条带宽度；
- 最小可靠间隙；
- 最小表面层数。

所有值都用模型毫米表示并在创建时校验。默认配置对应 0.4 mm FDM 喷嘴，
但不假装等同于某台具体设备的切片器能力。

### 2.2 PrintScale

XY 只使用一个换算：

```text
scale_mm_per_m = model_span_mm / max(bbox_width_m, bbox_height_m)
real_m_per_model_mm = 1 / scale_mm_per_m
```

例如成品有效跨度 196 mm：

| 真实取景 | 0.4 mm 喷嘴对应实地宽度 | 0.42 mm 线宽对应实地宽度 |
|---|---:|---:|
| 5 km | 10.2 m | 10.7 m |
| 15 km | 30.6 m | 32.1 m |
| 25 km | 51.0 m | 53.6 m |

Z 不按真实地理高度与 XY 等比例缩放。建筑、道路、水面和地标使用语义高度，
但所有厚度最终按层高量化，并满足最小表面层数。

## 3. 几何表现模型

### 3.1 三套网络，不再让一份路网承担所有职责

1. **拓扑网络**：尽量完整，仅用于连通性和候选街区构造，不直接渲染。
2. **结构缝网络**：只保留能分隔有效 block 的边界；优先用同材料浅缝表现，
   避免为了切块而把所有小路染成深色粗线。
3. **可见网络**：按道路等级、连通骨架、城市特征和局部墨量预算筛选，才进入
   灰色道路材料。

这样可同时保留 block base 的密度感和清爽的俯视视觉。

### 3.2 水体四级分类

- `major`：海面、大湖、大江，保留真实面形和城市级轮廓；
- `structural`：参与空间分区的主要河渠；
- `minor`：达到打印宽度且对构图有贡献的小河渠；
- `noise`：低于打印尺度或孤立碎片，不进入可见层。

大水体的黑色面积是构图留白，不与细碎道路使用同一种“墨量过多”惩罚。

### 3.3 墨量按语义和局部窗口计算

不再只看整张图的平均黑色占比，分别记录：

- 主水体占比；
- 陆地上的可见道路占比；
- 次级水体占比；
- 建筑/街区占比；
- 滑动窗口局部深色占比的 P95。

局部 P95 用于发现米兰、东京、上海等局部又黑又密的问题；主水体独立计分，
避免芝加哥湖面、东京湾因面积大而被错误削弱。

### 3.4 视觉焦点与 Z

后续引入确定性的 `FocusSpec`：候选来自高建筑、知名地标、河流转折、桥群、
环状/放射状路网中心和海湾轮廓。焦点区保留更多建筑并提高语义高度，背景区
更强聚合、更低高度、更少可见道路。Z 只在建网格前按语义映射和层高量化，
不对最终网格做全局拉伸。

## 4. 分阶段实施

### P1：道路职责分离

- 拓扑路网继续切 block；
- 从相邻有效 block 的公共边界生成结构缝；
- 可见路网单独按等级、连通性和打印宽度筛选；
- 统计输入路数、拓扑路数、结构缝数、可见路数，禁止“零道路但任务成功”。

阻断式验收不再使用单一城市。`data/print_regression_scenarios.json` 固化以下
核心矩阵：

| 城市 | 场景类型 | 必须守住的结构 |
|---|---|---|
| 芝加哥 | 高密棋盘路网 + 大湖 | 湖面、棋盘骨架、建筑密度；去掉防波堤噪声 |
| 北京 | 内陆环状/放射路网 | 环路、中轴、放射结构；支路不能淹没主结构 |
| 上海 | 高密建筑 + 宽江分割 | 黄浦江真实面形、两岸分区、局部墨量 |
| 西湖 | 山水湖泊 + 大江 | 西湖与钱塘江层级、地形、边缘留白 |

四个核心城市都必须生成 15 km 与 25 km 俯视图，并生成 25 km 正式 3MF。
米兰、东京、墨西哥城作为扩展观察组。任意一个必需运行或必需证据缺失，
`evaluate_result_set()` 都会阻止默认参数升级；不能再用单个漂亮样品宣称泛化成功。

P1 实现进度（2026-08-23）：

- `road_roles.py` 已将同一份 OSM 道路分为 topology / structural / visible；
- topology 仍用于构造街区，structural 只负责 block-base 结构缝，
  visible 才进入 PNG、GLB 和 3MF 的对比材料；
- 25 km 级可见道路执行“命名主干道连续分组 + 分级物理墨量预算”，
  互通匝道保留在拓扑中但不默认渲染，避免立交变成黑结；
- 道路宽度下限由成品比例、`min_colored_strip_mm` 和道路等级共同推导，
  同一个已解析倍率保存在 `LayerPolygons.road_roles` 和 `design_spec.json`
  中，预览与正式 mesh 不再各读一份全局参数；
- 画廊缓存 schema 已升级，道路倍率和打印配置均进入指纹。
