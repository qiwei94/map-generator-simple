# CompositionSpec：城市身份构图契约

`CompositionSpec` 是 15/25 km 城市模型的构图审计文件。它回答“哪些道路、水体是
画面的主元素，哪些只用于补足结构密度”，但不保存也不生成几何。

每次 `generate_city_legacy.py` 完成预处理后都会在输出目录写入
`composition_spec.json`；`--review-only` 也会写，因此评审图可以追溯到同一次角色
选择。正式 3MF 的 `design_spec.json` 会保存该文件名、schema 与 policy 版本。

## 固定分工

| 数据/模块 | 权限 | 明确禁止 |
|---|---|---|
| 高德 style-7 mask | 作为只读空间构图模板，把主路、次路和背景层级映射给重合的 OSM 线段 | 生成/描摹替代几何 |
| OSM | 提供道路、水体、建筑的精确源几何与名称/等级/宽度证据 | 因为数据多就全部显示为强前景 |
| 打印 profile | 约束喷嘴最小色条、缝隙、面积和高度 | 决定城市审美主次 |
| 角色选择器 | 输出 `primary`、`secondary`、`context`、`connector`、`background` | 控制 mesh 顶点、全局 Z 或布尔 |
| 渲染器/3MF builder | 按同一角色解析物理宽度；评审图可用灰度进一步表达主次 | 绕过打印下限把次级线变成不可打印细线 |
| Block base | 使用更密的 structural 网络保留街区切分和密度 | 要求每条结构线都成为深色材料 |

## 道路角色

- `primary`：与高德 major mask 持续重合的现有 OSM 主轴；未启用模板时使用原有
  环路保护与完整 identity 选择；
- `secondary`：与 arterial mask 持续重合的现有 OSM 走廊；
- `context`：只得到弱背景模板支持、但足以帮助读取城市密度的现有 OSM 线；
- `connector`：OSM-only 模式可用于短断口；高德空间模板模式仍不单独创建该角色，
  只有严格通过双端连续性检查的原始 OSM 短段才可继承主轴角色；
- `background`：继续参与 topology、block base 与结构缝，但不占高对比道路墨量。

空间模板模式不设全局目标墨量比例：参考图本身决定城市应有多少骨架，打印 profile
只裁决物理可行性。主路的打印宽度下限是 1.35 倍喷嘴色条，次路/背景路保持一个
喷嘴色条；所有角色仍受 `min_colored_strip_mm` 硬下限约束。评审 PNG 用灰度进一步
区分角色，这属于构图诊断，不等同于单一道路材料的正式 3MF 着色。

为避免“短支路垂直穿过粗主路 mask”被误判为主骨架，短 OSM way 必须同时满足：

1. 自身有足够模板覆盖；
2. 同名或同 ref 的完整走廊有持续覆盖；
3. 该走廊有足够受支持长度。

`*_link` 默认留在 topology 与 Block base。唯一例外是：同一走廊的两个已选、尚未
连通的端点之间只有一条原始 OSM link，路径不超过 250 m、绕行比不超过 1.35，且
名称/ref 连续；此时该短段可继承端点角色。算法不会生成坐标，也不会为了视觉闭合
描摹高德线条。

## 水体角色

- 达到场景占比的大水面直接成为 `primary`，例如海面、湖面、宽江面；
- 没有大水面时，完整候选中跨画幅、转折和高德显著性综合最高的一条成为主走廊；
- 命名护城河等紧凑城市身份围合可作为主元素；
- 其余已选完整河流/运河为 `secondary`，细碎水网只留在结构层。

水体仍使用项目现有统一材料逻辑；角色不会凭空创造河宽。OSM `width`、riverbank
和真实面形优先，高德只确认现有 OSM 走廊是否值得进入前景。

## 验收

审计至少检查：

1. `decision_contract.geometry_authority == "OSM source geometry"`；
2. 文件中没有坐标数组、mesh、Z 或 boolean 指令；
3. 25 km 输出存在可解释的主/次空间角色，背景网络仍用于 Block base；
4. 评审 PNG 与正式道路 builder 使用同一个角色化宽度解析函数；
5. 最终仍需真实 3MF 验证器 0 errors / 0 warnings；CompositionSpec 本身不能替代
   打印验收或人的审美判断。

## 2026-08-24 代表场景证据

北京与上海使用相同 25 km 参数、真实本地 PBF、已缓存高德显著性 mask 重算；为把
本轮耗时限定在道路/水体/构图，俯视对照使用平坦 DEM，因此不能作为地形性能或地形
质量证据：

旧的 identity-only 结果证明“高德只参与排序”远远不够：北京主路召回约 42%，上海
主路召回仅约 11%。因此新增实验分支把高德升级为空间模板，同时仍只输出 OSM
坐标。首轮 v6 结果如下（召回使用 4 px 对齐容差；可见道路是经过 BL 裁切后的数量）：

| 场景 | OSM 源道路 | 可见道路 | primary / secondary / context / connector | 高德 major / arterial 召回 | 水体判定 |
|---|---:|---:|---|---|---|
| 北京 25 km | 53,715 | 4,308 | 545 / 3,092 / 724 / 0 | 90.25% / 93.90% | 1.05% 大水面 + 筒子河围合为主元素 |
| 上海 25 km | 52,308 | 3,964 | 496 / 3,132 / 405 / 0 | 65.00% / 83.09% | 3.33% 黄浦江面为主元素，3 条完整河廊为次级 |

输出分别位于（`output/` 默认被 Git 忽略）：

- `output/skeleton_beijing_25km_v6/`；
- `output/skeleton_shanghai_25km_v6/`。

两张 v6 图比 identity-only 结果明显更接近高德骨架，但仍不是最终审美结论：上海
部分 OSM 线段存在缺口，北京/上海的单色正式材料无法复制高德彩色地图的三级灰度
观感。本模式保持显式 `--amap-salience cache|network`，尚未升级生产默认值，也未在
本实验分支重新部署 Web。

v6 仍暴露出一种稳定的伪影：25 km / 1024 px 下每个参考像素约 24 m，默认 3 px
容差会让垂直相交的小路在主路附近得到局部高覆盖；OSM 又常在路口切分 way，于是
只选中靠近主路的前一两段，形成梳齿状“线头”。v8 在角色选择后增加
`selected_osm_graph_leaf_chain_v1`：从选中图的自由端点追踪支链，删除不超过画幅
2.4%、悬空终止于主网的短链；两端连接、触及画幅边界、桥梁和隧道保持不动。被删
道路仍留在 structural/Block base，不改任何 OSM 坐标。

| 场景 | 剪枝候选 | 删除线段 / 累计长度 | 剪枝后角色 | BL 裁切后可见道路 |
|---|---:|---:|---|---:|
| 北京 25 km v8 | 4,361 | 691 / 139.3 km | 489 / 2,677 / 504 / 0 | 3,622 |
| 上海 25 km v8 | 4,033 | 891 / 194.5 km | 385 / 2,515 / 242 / 0 | 3,080 |

最终审计文件与俯视图位于：

- `output/skeleton_beijing_25km_v8/`；
- `output/skeleton_shanghai_25km_v8/`。

`composition_spec.json` 保存剪枝门槛、候选数、移除角色与累计长度。北京环路/故宫
矩形、上海黄浦江和跨区主轴在 v8 目视复核中仍保留；该判断不能替代后续更多城市
交叉验证。

v8 证明线头可以通过 OSM 图剪枝治理，但也暴露出另一侧问题：高德 mask 的像素洞、
OSM way 切分、名称/等级变化会把同一走廊切断。`print-road-roles-v10` 增加
`two_ended_original_osm_path_v1`，在剪枝之前沿原始 OSM 图寻找受约束的双端路径：

- 必须同时连接两个已选锚点，单端支路不会补回；
- 优先同名/ref 走廊；名称变化时要求两个锚点原本不连通且平均高德支持至少 0.42；
- primary / secondary / context 缺口上限分别为画幅 4% / 2.5% / 1.5%，总绕行比
  不超过 2.0；
- link 另受一条、250 m、1.35 绕行比和同走廊约束；
- 补回后再执行分角色剪枝：25 km 画幅 primary / secondary / context 短链门槛约为
  300 / 450 / 600 m，避免为了清除背景线头而伤及主轴。

1,437 条 link，立交形成明显结状噪声，因此被否决，未作为交付结果；v10 收紧后：

| 场景 | 补回线段 / link | 补回长度 | 后续删除线段 | 最终角色 primary / secondary / context | BL 裁切后道路 |
|---|---:|---:|---:|---|---:|
| 北京 25 km v10 | 543 / 47 | 34.7 km | 471 | 555 / 3,145 / 733 | 4,350 |
| 上海 25 km v10 | 443 / 3 | 30.3 km | 595 | 517 / 2,962 / 402 | 3,782 |

俯视图与审计文件位于 `output/skeleton_beijing_25km_v10/` 和
