# 第一步：负空间街缝与 C 街区接回正式 S6

状态：本地显式选项已接线，小范围自动回归通过；未部署、未重跑巴黎整城、未切片验收。

## 使用方式

在正常 `generate_model.py` 命令中显式追加：

```text
--urban-organization C --surface-road-style negative-space-v1
```

两者独立：C 决定建筑支撑街区组织；negative-space-v1 决定源道路连续性恢复、
0.28/0.42 mm 全缝宽和普通道路负空间表达。保留默认策略，避免把未经切片校准的
实验宽度冒充产品默认。物理 PrinterProfile 未修改，正式验收也未降低阈值。

## 阶段职责

- S6 接收 S5 Context 携带的源道路、源建筑与图层，不重新联网取数据。
- 显式 C 选项通过同一个 `run_s6_building_roles` 调用已存在的 C adapter。
- 按源身份恢复有足够已有支撑的连续道路，拒绝靠直线猜接；物理桥梁从源属性提取。
- 街块逐源裁切，不跨不同高度做全局 union；分裂后的每块保留原高度、源索引和源几何摘要。
- 地标裁切保留高度及平行的分类/高度角色属性；带 covered/tunnel 证据的走廊不切开地标。
- 普通道路是城市材料缺失处，不生成独立道路带；显式桥梁仍有共享面域和实体。
- S6 不再对该风格追加 10 m² 小碎片过滤。是否满足物理下限由后续验收处理，不静默丢失。
- S7 使用冻结的几何，负空间配色为灰底、浅色城市、黑色水体，不加建筑边线。
- S8 共用已有严格挤出；S6 输出几何和高度指纹继续在下游检查。

## 测试证据

分裂高度/来源、小碎片保留、地标高度与角色、covered 保护、显式 CLI、PNG 负空间。

`tests/test_surface_execution.py` 增加 negative-space-v1 参数化用例：真实 GLB 与生产
